# Builder Journal

> More than a portfolio—a journal of how I think, build, and learn.

## Overview

Builder Journal is my personal portfolio and a living record of my growth as a software engineer.

Rather than serving as a gallery of projects, this repository documents how I approach problems, make engineering decisions, collaborate with AI, and continuously improve through building products.

The goal is for visitors to understand the person before the engineer.

---

## Purpose

This project demonstrates:

- Product thinking
- Engineering decision-making
- Human-centered design
- AI-assisted development
- Continuous learning

---

## Project Philosophy

Every meaningful decision in this project is guided by these principles:

- Understanding before action.
- People before technology.
- Judgment over capability.
- Learning over ego.
- Every setback carries a lesson.

---

## Documentation

This repository intentionally separates different kinds of documentation.

| File            | Purpose                                        |
| --------------- | ---------------------------------------------- |
| `README.md`     | Project overview and setup instructions        |
| `SPEC.md`       | Product specification and requirements         |
| `CLAUDE.md`     | AI working agreement and development standards |
| `docs/prompts/` | Documented Claude Code prompts and reviews     |

---

## AI Collaboration

Claude Code is used as a development partner throughout this project.

Every significant AI interaction is documented, including:

- The goal
- The prompt
- Why the prompt was structured that way
- The outcome
- My review of the generated work
- Lessons learned

The objective is to demonstrate thoughtful collaboration with AI rather than blind acceptance of generated code.
