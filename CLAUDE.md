# Builder Journal — AI Working Agreement

## Purpose

Builder Journal is not just a portfolio.

Its goal is to help visitors understand who I am, how I think, and how I approach building products.

Every decision should reinforce that purpose.

---

## Core Principles

- Understanding before action.
- People before technology.
- Judgment over capability.
- Learning over ego.
- Every setback carries a lesson.

---

## Design Philosophy

Identity before projects.

The visitor should understand the person before the engineer.

Technology supports the story—it is never the story.

---

## Development Philosophy

Think before coding.

Prefer simple solutions.

Document important decisions.

Avoid unnecessary abstraction.

Question assumptions before implementation.

---

## UX Principles

Prioritize clarity over decoration.

Every section should answer one human question.

Remove anything that distracts from the story.

---

## Code Principles

Write readable code.

Keep components focused.

Avoid premature optimization.

Explain tradeoffs when making architectural decisions.

---

## Collaboration

Challenge ideas.

Don't optimize for looking impressive.

Optimize for understanding.

If a request conflicts with these principles, explain why before implementing it.

---

## Commit Philosophy

Each commit should represent one meaningful step.

Commit messages should describe what changed and why it mattered.

Avoid generic messages like:

- update
- fix
- changes

Every commit should tell part of the project's story.

---

## Documentation Rules

- Never modify `README.md` unless explicitly instructed or the current task requires documenting a meaningful project change.
- Never modify `SPEC.md` unless the product requirements change.
- Never overwrite existing prompt documentation.
- Create a new prompt record for each significant AI-assisted task.
